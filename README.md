# Эмулятор оболочки

Практическая работа №1, вариант 12. Этапы 1-5.

Консольный эмулятор UNIX-оболочки. В приглашении показываются имя VFS
и текущая папка: `deep:/home/user$`.

## Команды

- `ls [-l] [путь]` — содержимое папки, `-l` показывает тип и владельца
- `cd [путь]` — переход в папку, без аргумента в корень
- `head [-n N] файл` — первые N строк, по умолчанию 10
- `tail [-n N] файл` — последние N строк, по умолчанию 10
- `clear` — очистка экрана
- `chown владелец путь` — смена владельца файла или папки
- `rm [-r] путь` — удаление файла, `-r` для папки с содержимым
- `exit [код]` — выход

`chown` и `rm` меняют VFS только в памяти, JSON-файл не трогают.

Пути абсолютные (`/home/user`) и относительные (`docs`, `..`).
Аргументы в кавычках не разбиваются: `cd "my photos"`.
В приглашении имя VFS и текущая папка: `deep:/home/user$`.

Ошибки: неизвестная команда, незакрытая кавычка, лишние аргументы,
нет такого файла или папки, `cd` в файл, `head` для папки или
двоичного файла, неверное число строк.

Проверка всех команд и ошибок: `os_scripts\test_commands.bat`.

## Параметры

- `--vfs PATH` — путь к файлу VFS, имя файла становится именем VFS
- `--script PATH` — путь к стартовому скрипту

Оба параметра печатаются при запуске.

Стартовый скрипт — текстовый файл, по команде в строке. Строки с `#`
пропускаются, команда печатается вместе с приглашением, на первой
ошибке выполнение прекращается.

Скрипт для проверки параметров: `os_scripts\test_params.bat`.

## VFS

VFS грузится из JSON-файла в память, сам файл не меняется. Содержимое
всех файлов, и текстовых и двоичных, хранится в base64.

```json
{
  "name": "mydisk",
  "root": {
    "type": "dir",
    "children": {
      "readme.txt": {"type": "file", "base64": "SGVsbG8K"},
      "logo.png": {"type": "file", "base64": "iVBORw0KGgo="},
      "home": {"type": "dir", "owner": "user", "children": {}}
    }
  }
}
```

При загрузке base64 декодируется. Если получился текст, он лежит в
`content` узла, если байты не читаются как текст — файл помечается
двоичным и команды вроде `head` на него ругаются.

Готовые VFS в папке `vfs/`: `minimal.json` (пустая), `several.json`
(несколько файлов), `deep.json` (больше 3 уровней). Файлы `bad_*.json`
для проверки ошибок: не JSON, нет root, неизвестный тип, плохой base64.

Проверка всех VFS: `os_scripts\test_vfs.bat`.

## Запуск

В PowerShell нужно писать `.\run.bat`, в cmd просто `run.bat`.

Интерактивный режим:

```
.\run.bat
```

Имя VFS в приглашении (`mydisk:~$`):

```
.\run.bat --vfs vfs\mydisk.json
```

Выполнение стартового скрипта:

```
.\run.bat --script scripts\stage2.txt
```

Скрипт с ошибкой, выполнение прекращается, код выхода 1:

```
.\run.bat --script scripts\stage2_error.txt
```

Оба параметра сразу:

```
.\run.bat --vfs vfs\mydisk.json --script scripts\stage2.txt
```

Загрузка VFS:

```
.\run.bat --vfs vfs\deep.json
```

Все варианты параметров одной командой:

```
.\os_scripts\test_params.bat
```

Все варианты VFS и ошибки загрузки:

```
.\os_scripts\test_vfs.bat
```

Все команды и их ошибки:

```
.\os_scripts\test_commands.bat
```

chown и rm, плюс проверка, что файл VFS не изменился:

```
.\os_scripts\test_modify.bat
```

Можно запускать и напрямую: `python src\main.py [параметры]`.

## Пример

```
deep:/$ ls
etc/
home/
readme.txt
deep:/$ cd home/user
deep:/home/user$ ls -l
dir  user   docs/
dir  user   my photos/
deep:/home/user$ head -n 2 docs/notes.txt
1
2
deep:/home/user$ cd /readme.txt
cd: /readme.txt: это не папка
deep:/home/user$ exit
```
